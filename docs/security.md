# Security

## Threat model (short)

The rest-server runs in append-only mode so that a compromised backup client
cannot destroy its own backups. BelayPoint is the one component that **can**
delete backup data (`forget`, `prune`). Its compromise means loss of backups,
so it is protected more strictly than the clients.

Assets: the repositories (availability), the repository passwords
(confidentiality of the backed-up data), the `.htpasswd` file (who may write
to the rest-server).

Attackers considered:

- someone on the internet (must not reach BelayPoint at all),
- a misconfigured or compromised cloudflared/tunnel path,
- other devices or containers in the LAN without the admin password,
- someone with read access to the NAS disks or to a copy of `/config`
  (stolen disk, backup of the NAS, another container with the same mount).

Out of scope: root on the running NAS. Root can read process memory and
therefore the unsealed secrets; nothing in a container prevents that.

## Rules

1. **Not reachable from the internet.** BelayPoint is not part of the tunnel's
   Docker network and its port is published on the LAN address only.
   `internal/netguard` closes connections from outside the allowed networks
   before the TLS handshake (see "Network access" in architecture.md), and
   requests carrying Cloudflare headers are rejected. Only the TCP source
   address is used; forwarding headers are ignored.
2. **No host access.** No Docker socket, no worker containers, no self-update,
   two mounts only (`/repos`, `/config`). The container runs as the
   non-root owner of the repository files, read-only root filesystem, all
   capabilities dropped, `no-new-privileges`.
3. **Repository passwords only in memory.** Stored only in the vault
   (`/config/vault.json`), sealed with AES-256-GCM. The vault key is derived
   from the admin password with argon2id (m=64 MiB, t=3, p=2, random salt)
   and never written anywhere. Disk access alone gives ciphertext only. Each
   sealed entry is bound to its repository path via associated data, so
   entries cannot be swapped between repositories.
4. **Secrets in memory.** Held as `[]byte`, zeroed after use and on seal. No
   swap (`memswap_limit` = `mem_limit`), no core dumps. Passwords reach restic
   only through `--password-file /dev/fd/3` (pipe), never through arguments
   (visible in `ps`) or the environment (visible in `/proc/<pid>/environ`).
   restic gets an allow-listed environment. Job logs and UI output are
   filtered for the secret values.
5. **Sealed by default.** After every start nothing runs until the admin logs
   in. "Seal now" wipes the secrets immediately. Sessions live in memory only.
6. **Authentication.** One admin. Login = deriving the vault key and opening
   the key check; there is no stored password hash. At most one key
   derivation runs at a time (argon2id needs 64 MiB). Failed logins: 5 free,
   then exponential lockout up to 15 minutes (in memory, global, as there is
   one account). Optional TOTP as second factor; its secret is part of the
   vault. Random 256-bit session tokens, stored as SHA-256 only; cookie
   `__Host-belaypoint_session` with `HttpOnly`, `Secure`, `SameSite=Strict`;
   sliding expiry `BELAYPOINT_SESSION_TTL`. Admin password: 12 to 256
   characters; changing it re-encrypts the vault.
7. **TLS only.** No plain HTTP listener. Local CA and server certificate are
   generated by BelayPoint; fingerprints are logged at every start so the
   browser's view can be compared with the log before trusting it. The CA key
   never leaves `/config/tls/` (mode 0600).
8. **CSRF.** Go's `http.CrossOriginProtection` plus a per-session token on
   every state-changing request. `Cache-Control: no-store`, strict CSP
   (`default-src 'self'`).
9. **Input validation.** Repository paths only from discovery (relative to
   `/repos`, no symlinks, no `..`). Usernames match
   `^[a-z0-9][a-z0-9._-]{0,63}$`. Retention values are parsed into typed
   fields and passed as separate restic arguments. Cron expressions are parsed
   before saving. All external commands use `exec.CommandContext` with
   argument lists, never a shell.
10. **Deletion only through restic.** BelayPoint never removes files below
    `/repos` itself. `forget` and `prune` need a confirmation when started by
    hand (`forget` shows the `--dry-run` result first); `unlock --remove-all`
    needs the repository path typed. Only stale locks are removed
    automatically.
11. **`.htpasswd` integrity.** Atomic replace (temp file, `fsync`, `rename`),
    mode 0640 or stricter. The file is re-read and validated before each
    change; a file that cannot be parsed is never overwritten.
12. **Audit log.** Login, failed login, unseal/seal, password change, user
    changes in `.htpasswd`, repository password changes, job starts (manual
    and scheduled), settings changes. No secrets in entries.
